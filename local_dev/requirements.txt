# Python dependencies for the local development container. Not production's list.
#
# Why this file exists instead of `requirements.txt`: the repository's
# `requirements.txt` is a `pip freeze` of a conda environment on a developer's
# macOS laptop. It cannot be installed in a Linux container, and it is not a
# complete manifest of what this project imports:
#
#   * `appnope` is macOS-only; `conda-package-handling`, `conda_package_streaming`
#     and `pycosat` are conda's own plumbing and are not on PyPI in those versions.
#   * `drf_yasg` is imported by `measures/views.py`, `measures/views_stats.py`,
#     `missions/views.py` and `devices/views.py`, and is **absent** from
#     `requirements.txt`. Django cannot import the URLconf without it.
#   * `django_extensions` is in `INSTALLED_APPS` and is **absent** too, so
#     `manage.py check` fails before it reaches the database.
#
# Both of those are reported in LOCAL-DEV.md under "Known issues". Versions here
# match `requirements.txt` wherever it names one, so the container runs the same
# library versions as production; the two missing packages are pinned to the
# newest release compatible with Django 4.2 and DRF 3.15.
#
# `psycopg2-binary` replaces `psycopg2` so the image needs no build toolchain.
# `scipy` is dropped: nothing in the project imports it.
